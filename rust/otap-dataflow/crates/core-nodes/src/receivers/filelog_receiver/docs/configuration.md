# Filelog configuration

`config::Config::from_json` parses the engine node settings with field-path
errors. `Config::compile` consumes those settings and returns immutable
`CompiledConfig` inputs. Unknown fields
and unknown enum variants are errors. Byte sizes use the engine's shared unit
parser; durations use the same human-readable parser as nearby receivers.

Compilation has no filesystem side effects. It validates scalar and interacting
limits, compiles glob sets and the optional multiline boundary, selects the
checkpoint ID, derives the checkpoint compatibility profile, and checks the
configuration resource models. Snapshot and recovery bounds are derived by
portable checkpoint-crate helpers on every platform. The Linux store uses the
same admission calculation before opening its namespace.

## Paths

The caller supplies an absolute base for relative patterns. This freezes their
lexical interpretation; it does not select or provision the engine state root.
Compilation never reads the process working directory to choose a base.
An integration without an explicit base passes an empty path and accepts only
absolute patterns. No state-root or working-directory fallback is permitted.
Absolute patterns do not require a UTF-8 base. Pattern text is UTF-8, while Unix
candidate paths retain their native bytes, including invalid UTF-8.

Globs use `globset` syntax with literal separators: `*` and `?` do not cross a
separator, while `**` supports recursive components. Unix backslashes escape
metacharacters. Literal traversal prefixes remove those escapes. Brackets and
alternation remain glob syntax, so a conservative prefix may be shorter than
its eventual matching directory. Parent-directory components are rejected.
Literal prefixes retain their spelling; empty or dot components after a
wildcard and patterns ending in a separator are rejected with their entry index.
Directory-depth bounds are derived from the translated syntax. Unambiguous
directory components are also matched by name before descent. A `**` component
permits arbitrary depth after its preceding components match. Alternatives or
classes containing separators use a compiled directory-prefix expression that
preserves their name and branch constraints without enumerating combinations.
Flat file globs do not traverse unrelated child directories.

The policy exposes ordered include and exclusion roots. Discovery resolves
these roots and retains their verified mappings. Startup calls
`validate_root_lengths` with the chosen scanner capacity before constructing the
scanner; failures identify the include or exclude entry. It checks exclusions against
both the lexical path and verified target, then calls `excludes_mapped` with
the target's relative suffix under each canonical exclusion root. The suffix
matcher evaluates the full remaining pattern without constructing a joined
path. It never excludes an entire prefix merely because one pattern uses it.
Only an explicit matching `/**` suffix authorizes subtree pruning.

Globset translates syntax; the same bounded regex compiler and scratch model
used by multiline matching compiles the generated byte expressions. Identical
expressions are deduplicated. A set's checked program budget derives from its
expanded byte syntax: literal bytes, class ranges, branches and repetitions.
Short patterns do not each reserve a 10 MiB program allowance. The coefficient
covers Thompson states, edges and forward/reverse programs for the pinned
engine; the existing multiline program ceiling is unchanged. Lazy caches retain
the existing
2 MiB limit with equivalent NFA fallback. Configuration errors identify a
program that cannot fit its derived execution budget. These are implementation
limits, not new YAML settings.

Mapped exclusions share one indexed program and one PikeVM cache; directory
component predicates use another shared indexed program. Neither reserves a
lazy-DFA cache per pattern. Pattern IDs keep canonical-root mappings distinct.

The path policy owns explicit worker-local scratch, with no pooled search cache
or cross-worker lock. It is movable to a worker but is not shared concurrently.
Unix matching borrows native path bytes and does not allocate joined paths.
`CompiledConfig::into_paths()` transfers ownership to the discovery worker
after other startup inputs have been extracted. `retained_bytes()` reports
program, metadata, root-storage and bounded scratch allowances. The regex
metadata allowance is source-audited for the locked engine
and checked against cold allocations separately from the growing scratch
allowance in an isolated allocation test. Allocator overhead and
transient compilation admission remain separate from this requested-byte model.

An invalid mapping index or non-relative suffix fails closed. A path-policy
match is not source identity, filesystem verification, or permission to read.
The policy does not implement symlink handling, recursive traversal, or scan
scheduling. Linux is the initial execution target; Windows native-path handling
and filesystem behavior still require their platform qualification.

## Checkpoints

An explicit `checkpoint.id` selects its exact namespace. Otherwise the ID uses
the specified versioned SHA-256 recipe over length-prefixed pipeline-group,
pipeline, and node IDs. Runtime placement and discovery settings do not affect
it. The checkpoint crate validates and encodes the exact ID into its lowercase
hexadecimal directory component; the store uses the same implementation.

Changing an explicit ID or any input to the automatic ID selects another
namespace. There is no sibling search or automatic migration. The compatibility
profile uses the checkpoint codec's existing canonical digest implementation.

## Resource and startup boundaries

Configuration rejects overflow and enforces the provisional 1 GiB identity
model and store recovery/file ceilings. It calculates the reader-table model,
selected primitive's payload peak, maximum snapshot, and maximum logical record
size. It exposes the capped WAL, complete checkpoint, and separate recovery-phase
bounds. Failures distinguish arithmetic overflow from a calculated value above
its ceiling, and include the contributing settings.

The known partial-state floor includes one owned source-turn remainder. The
batch/carry-over projection and the sum of path and multiline matching charges
are checked separately; shared immutable programs and worker scratch remain
visible as distinct charges. Logical record admission includes conservative
metadata for the selected
export mode and fragment/terminal attributes. It uses the effective newline
body limit or multiline record limit, rather than summing framing limits.

`CompiledConfig` does not mean the receiver is ready. Startup must still:

- Obtain the engine's provisioned state-root capability and open the selected
  namespace under the store's ownership and recovery contract.
- Resolve include/exclusion roots, reject direct inclusion of the opened
  checkpoint namespace, and enforce namespace identity exclusion before reads.
- Check discovery verification capability, engine allocation, and downstream
  aggregate completion requirements before reporting Ready.
- Admit the complete runtime memory model: reader/continuity metadata,
  partial-state slots, regex construction and each retained worker's scratch,
  channels, leases, batch/carry-over physical state, and worker/library overhead.
  Reuse the reported known charges without double-counting shared storage.
- Check each deadline when scheduling it and each runtime counter increment.

The partial-state check here is a necessary payload-plus-remainder floor. It is
not
a completed slot size or slot count. Runtime admission must add the concrete
reader state before allocating slots; a compiled configuration can still fail
that admission. The configuration models do not establish an RSS guarantee.
